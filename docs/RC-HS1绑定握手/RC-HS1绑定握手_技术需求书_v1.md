## 1. 背景与目标

整套遥控器由"蓝牙芯片 + 4G 模组"两颗独立固件组成。为防止第三方用非授权模组搭配我方蓝牙固件工作，
需要在模组固件中增加一条**本地 AT 指令**：由蓝牙芯片出随机题，模组用预置密钥算出答案回传，蓝牙芯片校验。

- **只用一条指令**（外加一条自检指令）；
- **约 20 行核心代码**，无查表、无动态内存、RAM < 32 B；
- **不涉及网络 / SIM / 协议栈**，纯本地运算。

下面按"实现内容 → 接口 → 算法 → 密钥 → 要求 → 自测 → 待答复"的顺序展开。

## 3. 接口定义

### 3.1 通道与帧格式

| 项 | 约定 |
|---|---|
| 物理通道 | 蓝牙芯片 USART1 ↔ 模组 AT 串口 |
| 编码 | ASCII，十六进制大写（解析端建议大小写都接受） |
| 帧 | 标准 AT 行：`AT+...<CR><LF>`；应答 `+RCHS: ...<CR><LF>OK<CR><LF>` |
| 主机 | 蓝牙芯片（挑战发起方 / 校验方） |
| 从机 | 4G 模组（应答方） |

### 3.2 命令一：能力探测 / 密钥校验值

```
主机 → 模组 : AT+RCHS?
模组 → 主机 : +RCHS: <ver>,<kcv>
            OK
```

- `<ver>`：1 位十六进制，协议版本，当前固定 `1`；
- `<kcv>`：8 位十六进制（4 字节），密钥校验值 = `XTEA(K, 0000000000000000)` 的前 4 字节；
- 该 `idx` 无对应密钥时回 `ERROR`；
- 用途：产测比对"两边密钥是否一致"、固件兼容性探测。

### 3.3 命令二：挑战应答

```
主机 → 模组 : AT+RCHS=<idx>,<nonce>
模组 → 主机 : +RCHS: <resp>
            OK
```

| 字段 | 长度 | 说明 |
|---|---|---|
| `<idx>` | 1 位 hex | 密钥索引 0～F。本期固定 `0`，为"分批 / 每台唯一密钥"预留 |
| `<nonce>` | 16 位 hex = 8 字节 | 主机随机数（挑战），大端字节序 |
| `<resp>` | 16 位 hex = 8 字节 | 模组应答，大端字节序 |

整行约 35 字节（比现有 `AT+ECSOST` 等指令短得多）。

### 3.4 错误与异常

| 情况 | 模组返回 |
|---|---|
| 未配置密钥 / idx 无效 | `ERROR` |
| 参数长度或字符非法 | `ERROR` |
| `nonce` 全 0，或与上一次 `nonce` 完全相同 | `ERROR`（建议实现） |
| 正常 | `+RCHS: <resp>` + `OK` |

### 3.5 时序

| 项 | 约定 |
|---|---|
| 模组响应时间 | **< 50 ms** |
| 主机超时 | 300 ms（超时 / `ERROR` / 应答不匹配，均计一次失败） |
| 可用时机 | 模组启动完成（能应答 `AT`）后立即可用，不依赖 SIM / 网络 |

## 4. 算法

### 4.1 公式

```
resp[8] = XTEA_encrypt_32cycles(key = K[idx][16], block = nonce[8])
```

### 4.2 参数与字节序

- **XTEA**（Wheeler & Needham, 1997）：64-bit 分组、128-bit 密钥、**32 cycles（64 Feistel 轮）**，
  `delta = 0x9E3779B9`；
- 字节序：**全程大端**
  - `k[0..3] = BE32(K[0..3]), BE32(K[4..7]), BE32(K[8..11]), BE32(K[12..15])`
  - `v0 = BE32(nonce[0..3])`，`v1 = BE32(nonce[4..7])`
  - 输出 `resp[0..3] = BE32(v0')`，`resp[4..7] = BE32(v1')`

### 4.3 资源占用

约 20 行核心代码，无查表，RAM < 32 B；单次运算在微秒级，对模组几乎无额外负载。

### 4.4 选用理由与参考实现

XTEA 为公开算法，有官方测试向量可交叉验证（避免自研算法两边实现不一致），且比 AES 更省 Flash / RAM。
完整参考实现（含 hex 编解码与自测 `main()`）见附件 `rchs_ref.c`，编译运行应输出 `SELF-TEST PASSED`。

## 5. 密钥

| 项 | 约定 |
|---|---|
| 长度 | 16 字节 |
| 配置方式 | **按批次编进模组固件**（本期不需要可写存储，也不需要产测写密钥命令） |
| 变更方式 | 换批次时随固件一并更新，按固件版本登记 |
| 校验 | 两端各自算 KCV，产测台架比对，不一致即报警 |
| 粒度 | 按批次一把；`idx` 已为"每台唯一密钥"预留扩展位 |
| 可选 | 若贵方标准流程要求"可写密钥"，请告知可用 NV 存储与写入方式，双方再协商 |

密钥**绝不出现在 UART 报文里**，只参与本地运算。

---

## 6. 模组侧实现要求

1. **任意网络状态可用**：未插卡、未注册、已开 socket、传输中都要能应答（纯本地运算，不依赖网络）。
2. **上电即可用**：模组启动完成（能应答 `AT`）后立即可应答 `AT+RCHS`，不需要等 SIM / 网络就绪。
3. **不干扰既有 URC**：`+RCHS:` 是命令应答行，不得与 `+ECSONMI` 等 URC 混淆；不得改变现有 AT 行为。
4. **响应时间** < 50 ms。
5. **重放保护**：拒绝与上一次相同的 `nonce`（RAM 保存上一次即可，模组重启后清零无妨）。
   nonce 由主机生成（每次不同），模组无需关心其生成方式。
6. **回显**：`ATE0` / `ATE1` 两种模式下都要正确响应（主机解析以 `+RCHS:` 冒号区分回显行 `AT+RCHS=`）。

## 7. 自测方法与标准向量

### 7.1 XTEA 官方向量（验证算法本身）

| # | key（16 字节） | nonce（8 字节） | 期望 resp |
|---|---|---|---|
| 1 | `00000000000000000000000000000000` | `0000000000000000` | `DEE9D4D8F7131ED9` |
| 2 | `0123456789ABCDEF0123456789ABCDEF` | `0123456789ABCDEF` | `27E795E076B2B537` |

这两条来自 XTEA 官方参考实现，**与业务密钥无关**，专门证明"算法本身没写错"。

### 7.2 协议向量（测试密钥 = ASCII `RCHS-TEST-KEY-01`）

测试密钥十六进制：`524348532D544553542D4B45592D3031`

| # | 串口发送 | 模组必须回 |
|---|---|---|
| 1 | `AT+RCHS=0,0000000000000000` | `+RCHS: 50D38D93C8049961` + `OK` |
| 2 | `AT+RCHS=0,0102030405060708` | `+RCHS: 61AA3ADB1E6E9224` + `OK` |
| 3 | `AT+RCHS=0,FFFFFFFFFFFFFFFF` | `+RCHS: BA809F9A860D83C7` + `OK` |
| 4 | `AT+RCHS=0,0011223344556677` | `+RCHS: 815A333B1F39EA7E` + `OK` |
| 5 | `AT+RCHS=0,A5A5A5A5A5A5A5A5` | `+RCHS: ED3121A623B7DA73` + `OK` |

体检指令：

| 串口发送 | 模组必须回 |
|---|---|
| `AT+RCHS?` | `+RCHS: 1,50D38D93` + `OK` |

> 测试密钥只用于联调自测，**不得用于量产**。

### 7.3 自测方法

```
gcc -O2 rchs_ref.c -o rchs_ref
./rchs_ref
```

```

XTEA official #2 got 27E795E076B2B537 expect 27E795E076B2B537 OK
RCHS vector #1 ... OK
...

```

> Windows 下产物为 `rchs_ref.exe`。也可用贵方现成的 XTEA 库，只要 32 cycles、大端字节序，结果应完全一致。

### 7.4 密钥校验值（KCV）说明

```
KCV = XTEA(K, nonce = 0000000000000000) 的前 4 字节，8 位十六进制
```

产测时读 `AT+RCHS?`，把模组返回的 KCV 与蓝牙芯片算出的 KCV 比对，**一致即证明两边密钥配对**，
无需拆机、无需暴露密钥本身。
