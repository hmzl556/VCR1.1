# 新板按键映射与 HID 适配工作流程

> 日期：2026-11-17
> 背景：新板（29 键 = 28 矩阵 + 1 独立）原理图已定稿（doc/遥控器按键），硬件无风险（见 doc/BR1601键盘扫描应用笔记勘误.md）。当前手头只有旧板（18 键），用飞线在旧板焊盘上模拟新板按键，先枚举"线对 → 厂商键位 KEY_n"，再实现 HID 映射。

## 阶段 1：按键枚举（诊断构建，用旧板飞线）

目的：把新板 29 个键的"线对 → 厂商 KEY_n → 按键功能"关系全部实测确认。

已知：
- 新板 28 个矩阵键的线对已从原理图网表提取（见阶段 3 附表）；
- 独立键 数字0 = PA0 低有效 = KEYDATA0 bit0 = 厂商 **KEY_29**（已实测）；
- 矩阵 (PA1,PA3) = KEYDATA1 bit4 = 厂商 **KEY_5**（已实测，表4 勘误）；
- 其余 26 对线对的 KEY_n 以表4（含勘误）为准，需逐对飞线验证。

### 诊断方案（待用户拍板）

**方案 B（推荐）**：保持现有 18 键映射不动，重新启用上次验证过的原始寄存器打印（KEYDATA0~4，主循环打印）。飞线短接每个新键线对 → 从打印的 word1/word0 位直接得 KEY_n（word1 bit N → KEY_(N+1)；word0 bit N → KEY_(N+29)）。
- 优点：零功能风险（旧键照常工作、组合键/电源/语音语义不错乱）、改动最小（重开诊断宏即可）、信息与方案 A 完全等价。
- 缺点：需要人肉换算 bit→KEY_n（一步减法）。

**方案 A（用户原方案）**：注释 18 键映射、启用 SDK 原 44 键映射（KEY_1~44），打印匹配到的 map 索引（key id）。
- 优点：直接打印"对应 keyscan_map 第几条"。
- 缺点/注意：
  1. enum 需扩展到 KEYSCAN_KEY44（KEYSCAN_KEY_MAX=45）；
  2. **诊断期间键号语义全部错位**：TASK_KEYSCAN_KEY1~18 宏指向的物理键全变——长按 id=1 会进红外学习、id=15 会触发语音、id=18 会被当机顶盒电源，组合键 14+3/9+3 也可能误触发。枚举时**只短按**、别长按；
  3. 该 44 键映射表是临时诊断用途，最终新板固件按阶段 3 的决策处理。

### 枚举操作步骤

1. 编译烧录诊断构建（方案 A 或 B）；
2. 按新板原理图逐个飞线短接 28 个矩阵线对（旧板任意两个对应线位的焊盘），每次按住 0.5s 松开，记录打印值 → KEY_n；
3. 独立键：PA0 焊盘飞线经按键到 GND，记录 KEY_29 确认；
4. 产出完整表：`功能键 → 线对 → KEY_n`（28+1 行），与表4（含勘误）逐行对照，不一致处标红找原厂确认；
5. 关闭诊断宏，回退诊断代码。

## 阶段 2：定表（甲方确认，不写代码）

1. **HID 键值口径**：按 GY/T 407-2024 表B.1 标准值，还是维持歌华私有值？已知分歧三处：
   - KEY3（现电视/新板电视机业务）：当前 0x55 歌华私有，标准 0x4A；
   - KEY17 回看：当前 0x41 歌华私有，标准 0x91；
   - KEY18 机顶盒电源：当前 0x0C 歌华私有，标准电源统一 0x66；
   - 新键（直播业务 0x3D、设置 0xEB、数字 0x1E~0x27 等）无私有历史，默认按标准。
2. **设置键 vs 信源键**：甲方列表有"设置"无"信源"，原理图有"信源"无"设置"——确认最终 29 键清单。
3. 产出最终映射总表：`功能键 → KEY_n → HID usage (page/ID)`，作为阶段 3 的唯一依据。

## 阶段 3：固件实现

1. **映射表决策**（待定）：
   - 方案一：直接启用 SDK 原 44 键映射作为生产映射（KEY_n 即键号），`task_keyscan.h` 的 TASK_KEYSCAN_KEY* 宏按新板重新分配；HID switch 的 case 按 KEY_n 填；
   - 方案二：新建 29 键产品映射（沿用现在 18 键映射的风格：产品键号 + 厂商位），HID switch 按产品键号填。
   - 推荐方案一：映射表与 SDK 一致、枚举结果直接可用、注释表即可维护。
2. HID switch（ble_hid_kbd.c）：29 个键的 case 按阶段 2 总表填写（含消费类 音量± is_consumer=true），删除/保留 30~44 的 QWERTY 残留按需清理；
3. RC-KEY-NOTIFY 分类：新键 key_type（键盘/消费类）与 usage 跟随 HID；
4. 组合键按标准改造：机顶盒配对 14+直播业务、解配 9+直播业务、电视配对 14+电视机业务、解配 9+电视机业务、用户码 12+主页 / 12+菜单、出厂 8+14+确认（线对已过共线检查，见前文）；
5. 业务键模式切换（活跃设备标志）+ 红外路由按标准 5.1.1.3 的"控制对象"列（后续阶段）；
6. 独立键 数字0：映射条目 `{0x00000001, 0x00000000}`，HID case，处理链分支。

## 阶段 4：验证

1. 主机回归（tools/test_base_merge.py 等全部通过）；
2. 旧板飞线冒烟：29 键逐个按，HID 报文 usage 正确（nRF Connect 看报文或机顶盒响应）；
3. 新板到货后：上板全键回归 + 组合键 + 学习 + 长按重复；
4. 关闭/移除所有诊断代码。

## 待用户拍板的问题

1. 阶段 1 用方案 A 还是 B（推荐 B）；
2. 阶段 3 映射表用 SDK 44 键编号还是新建产品编号（推荐 SDK 编号）；
3. HID 键值口径：标准表B.1 还是保留三处歌华私有（需甲方确认）；
4. 设置/信源键最终清单。

## 实施记录（2026-11-17）

用户决策：① 所有按键按新原理图线对；② 用 SDK 44 键编号做生产映射；③ 旧键 HID 保持不变（电视业务 0x55、回看 0x41、机顶盒电源 0x0C 歌华私有保留），新键按标准；④ "信源"键实为点播，HID/红外暂借设置码 0xEB/0x8D。

**枚举完成（旧板飞线实测，29/29）**：KEY_1~28 依次对应原理图 28 个矩阵线对（与 SDK 位序一致），KEY_29 = 数字0 独立键（PA0 低有效）。

**已实现**：
1. 生产映射启用 SDK 44 键表 + enum 扩展（KEYSCAN_KEY_MAX=45），`KEYSCAN_DIAG_BUILD` 与诊断打印已清理；
2. TASK_KEYSCAN_KEY1~18 宏重分配 + 新增 LIVE(12)/VOD(14)/DIGIT0~9 宏；
3. HID switch 29 键（旧键不变、新键按表B.1、点播 0xEB）；
4. 组合键改标准 §7.2b：机顶盒配对 = 音量-+直播业务(7+12)、解配 = 返回+直播业务(19+12)（BLE 仅配机顶盒，电视纯红外）；
5. 红外重编号：RC6 表 13 键、NEC 表 29 键（含数字键 0x87~0xCC、直播 0x3D、点播借 0x8D）；
6. 学习键集合改为 {1 电视电源, 11 回看, 14 点播, 23 电视业务}，wave store VERSION=2 + 紧凑槽位 0..3（旧学习数据作废，需重新学习）；
7. Tag10 键值重编号（语音 16→13/14 等）；
8. 主机测试全部重写为新键号并全部通过（test_ir 11 组 + test_base_merge 13 组 + rc_session/voice/battery/baud）。

**待办**：
