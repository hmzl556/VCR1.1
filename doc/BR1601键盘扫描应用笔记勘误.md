# BR1601 键盘扫描应用笔记勘误与实测记录

> 记录日期：2026-11-07
> 对象：《BR1601_键盘扫描应用笔记》V1.0（BR1601A01/A02/B01/B02）
> 方法：旧板（18 键，8 条矩阵线全部引出）飞线实测 + SDK 源码核对

## 勘误清单

### 勘误 1：44 键键盘 IO 列表 PA10 ↔ 键值表 PB10 不一致

- 笔记 3.1.2 节"44 键键盘：PA0、PA1、PA2、PA3、PA6、**PA10**、PB8、PB9"
- 表 4 键值表中对应线为 **PB10**（如 PB10-PA6、PB9-PB10 等交叉对）
- 结论：**以 PB10 为准**（表 4、SDK 映射、现有固件三方一致；笔记 IO 列表为笔误）

### 勘误 2：表 4 漏标 INFO1 bit4 = (PA1, PA3)

- 笔记第 3 节 44 键键盘原理图中画有 PA1-PA3 交叉的按键，但表 4 的 INFO1 键值表缺失该线对（表中该位为"-"空位）
- 实测（2026-11-07）：旧板飞线短接 PA1 与 PA3，KEYDATA1（INFO1）**bit4 置位**（原始值 `00000010`），且该位在现有 18 键映射中未被占用，测试结果干净
- 结论：**图对表错**。硬件扫描全部 C(8,2)=28 个矩阵交叉对，表 4 应补：INFO1 bit4 = (PA1, PA3)，对应 SDK 键位 KEY_5
- 对设计的影响：新版原理图 28 对全互联矩阵**全部有效**，"上"键（PA1-PA3）可正常使用，无需避让

## 独立键实测记录

- 硬件通道：KEYDATA0（INFO0）即独立键寄存器，SDK `KEYSCAN_ReadKeyData()` 一次读出 5 字（KEYDATA0~4），读取通道可用
- 位语义（实测 + 推断）：
  - **bit0 = PA0 低有效（按下接 GND）——已实测**（飞线 PA0-GND，KEYDATA0 置 `00000001`）
  - 推断（未逐一实测）：bit0~7 = PA0/PA1/PA2/PA3/PA6/PB8/PB9/PB10 低有效，bit8~15 = 同序高有效（按下接 VCC）；依据为 SDK 原 44 键映射 KEY_29~KEY_44 的排列与笔记原理图 SW29~SW44 的接线顺序
  - 如需使用更多独立键位，用一根飞线验证目标位即可
- 空闲稳定性：空闲时 KEYDATA0 恒为 `00000000`（500ms 周期打印长时间观察），无上拉的独立键方案在实机上稳定
- 屏蔽规则：独立键按下时（KEYDATA0≠0）所有矩阵键匹配失败，与笔记"有独立键按下时忽略矩阵按键区域"一致
- 固件支持现状：驱动层读取通道完整；极性配置在 SDK 驱动中**未暴露**（KEYSCAN_InitType 仅 Mask/Mode/Wts/Dts/Int_en）；应用层现有 `keyscan_map` 的 word0 恒 0，独立键条目写成 `{0x00000001, 0x00000000}` 即可被现有 memcmp 匹配逻辑识别，仅需新增映射条目与键值处理分支

## 对 44 键方案的最终结论

- 8 条线（PA0/PA1/PA2/PA3/PA6/PB8/PB9/PB10）= 28 个矩阵键（全互联，全部有效）+ 16 个独立键位（8 线 × 高/低各一）= 44 键容量，与笔记一致
- 新版原理图（28 矩阵 + 1 独立 = 29 键）无硬件风险，PCB 可按图定稿
- 低功耗扫描模式（8 IO）容量为 20 键（见固件注释），29 键布局只能使用自动扫描模式
