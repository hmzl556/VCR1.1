### 1.2 现有"状态"推断方式
当前代码没有显式状态机，系统行为通过以下全局变量组合推断：

| 变量 | 含义 | 说明 |
|------|------|------|
| `bleAdvStat == 0xa6` | BLE栈+广播已初始化 | 仅表示 `myBleStartAdv()` 已调用完成，不代表当前正在广播（如连接成功后广播会停止） |
| `bleConnectOk == 0xa6` | BLE已连接 | 连接成功回调中置位，断连回调中清零 |
| `g_peer != NULL` | 当前有连接对端 | 连接时赋值，断连时置NULL |
| `peer_bonded_count() > 0` | 有绑定记录 | 决定断连后启动配对广播还是回连广播 |

> **注意**: `bleAdvStat` 只在初始化时设置一次（`task_ble.c:38-43`），后续断连重广播不会改变它，因此它不能用于判断"当前广播是否在运行"。当前代码通过 `ble_adv_stop()`/`ble_adv_start_by_bonding()` 直接控制广播启停，没有维护广播运行状态变量。

### 1.3 关键发现
- 连接参数已支持范围配置：`BLE_CONN_INTV_MIN_5MS`(5ms) ~ `BLE_CONN_INTV_MAX_50MS`(50ms)，latency 40~100
- 当前工作态参数：10ms / latency 40，符合待机态参数梯度要求的基础
- 芯片 BR1601x 已提供 `PWR_EnterPDMode()` 用于深度休眠，`EXTI` 支持按键唤醒，`RTC` 支持定时唤醒
- KEYSCAN 已配置中断模式（EXTI_LINE13），可在休眠时唤醒

### 2.2 五种状态详述

| 状态 | 广播 | 连接 | 连接参数 | 功耗特征 | LED |
|------|------|------|----------|----------|-----|
| **PAIRING** | 可发现可连接 | 无 | — | 高（持续广播） | LED2快闪(200ms) |
| **RECONNECTING** | 不可发现可连接 | 无 | — | 高（持续广播） | 灭 |
| **WORKING** | 关闭 | 有 | 10ms/latency40 | 基准 | 按键时亮 |
| **STANDBY** | 关闭 | 有 | 50ms/latency100 | 低(≤65μA) | 灭 |
| **SLEEP** | 关闭 | 无 | — | 极低(≤20μA, Sleep模式1.6μA) | 灭 |

### 2.3 状态转换条件

| 转换 | 触发条件 | 动作 | 备注 |
|------|----------|------|------|
| 上电 → PAIRING | 上电且无绑定 | 启动配对广播 | 当前已实现 (`ble_adv_start_by_bonding`) |
| 上电 → RECONNECTING | 上电且有绑定 | 启动回连广播 | 当前已实现 (`ble_adv_start_by_bonding`) |
| 任意 → PAIRING | 断连且无绑定；休眠唤醒且无绑定 | 启动配对广播 | **补全**：断连+无绑定场景 |
| 任意 → RECONNECTING | 断连且有绑定；休眠唤醒且有绑定 | 启动回连广播+重试计时 | 当前已部分实现 |
| PAIRING → WORKING | 连接成功 | 停止广播，切换工作态参数 | **补全**：当前代码在 `ble_gap_connected` 中实现 |
| RECONNECTING → WORKING | 连接成功 | 停止广播，切换工作态参数 | 当前已实现 |
| RECONNECTING → SLEEP | 回连广播45s无连接 | 停止广播，进入PD休眠 | **新增** |
| WORKING → STANDBY | 无业务(按键/语音/CAT1) 8s | 切换大连接参数，关闭非必要外设 | **新增** |
| WORKING → PAIRING | 断连且无绑定 | 启动配对广播 | **补全**：取决于 `peer_bonded_count()` |
| WORKING → RECONNECTING | 断连且有绑定 | 启动回连广播 | 当前已实现 (`ble_gap_disconnected`) |
| STANDBY → WORKING | 按键/语音触发/对端数据/CAT1数据 | 恢复工作态参数，开启外设 | **新增** |
| STANDBY → SLEEP | 无业务45s | 断开连接，进入PD休眠 | **新增** |
| STANDBY → PAIRING | 断连且无绑定 | 启动配对广播 | **新增** |
| STANDBY → RECONNECTING | 断连且有绑定 | 启动回连广播 | **新增** |
| SLEEP → PAIRING | 按键/RTC唤醒且无绑定 | 重新初始化BLE栈+配对广播 | **新增** |
| SLEEP → RECONNECTING | 按键/RTC唤醒且有绑定 | 重新初始化BLE栈+回连广播 | **新增** |

### 3.1 `pmu/inc/pm_config.h` — 配置参数

```c

#define PM_WORK_TO_STANDBY_MS     8000    // 工作态→待机态：8s无业务
#define PM_STANDBY_TO_SLEEP_MS   45000    // 待机态→休眠态：45s无业务

#define PM_STANDBY_CONN_LATENCY      100  // 最大延迟数
#define PM_STANDBY_CONN_TIMEOUT      800  // 超时

// ====== RTC 唤醒间隔（休眠态） ======
#define PM_SLEEP_RTC_WAKEUP_SEC       5    // 每5秒唤醒一次检查
```

### 3.2 `pmu/inc/pm_state.h` — 状态机API

```c
typedef enum {
    PM_STATE_PAIRING = 0,

// 初始化
void pm_state_init(void);

// 获取/设置当前状态
pm_state_t pm_state_get(void);

// 业务活动通知（reset空闲计时器）
void pm_activity_notify(pm_activity_t activity);

// 连接事件通知

// 每主循环周期调用，处理超时
void pm_state_process(void);

```

### 3.3 `pmu/src/pm_state.c` — 状态机核心

核心逻辑：
1. 维护当前状态 `g_pm_state`
2. 维护 `g_pm_last_activity_ms` 空闲计时器
3. 维护回连重试计时器 `g_pm_reconnect_start_ms`
4. `pm_activity_notify()`: 被按键/语音/CAT1调用，刷新时间戳，若在待机态则切回工作态
5. `pm_state_process()`: 每循环检查超时条件，执行状态转换
6. 状态转换时调用 `pm_standby_enter/exit()` 或 `pm_sleep_enter()`

### 3.4 `pmu/src/pm_standby.c` — 待机态管理

进入待机态动作：
- 调用 `le_conn_update()` 切换连接参数到 (50ms, latency 100)
- 关闭 LED
- 关闭 CAT1 发送功能（保持接收）
- 可选：关闭 ADC、关闭非必要时钟

退出待机态动作：
- 调用 `le_conn_update()` 切换连接参数回 (10ms, latency 40)
- 恢复 CAT1 发送
- 恢复 LED

### 3.5 `pmu/src/pm_sleep.c` — 休眠态管理（Sleep 模式）

进入休眠动作：
- 停止广播
- 断开 BLE 连接（如果有）
- 关闭所有非必要外设（LED、CAT1 UART、ADC、MICBIAS等）
- 配置 KEYSCAN EXTI 唤醒源（EXTI_LINE13，已在 `app_keyscan.c` 初始化）
- 配置 RTC 唤醒定时器（LSI 32KHz，周期 5s）
- 调用 `PWR_EnterSLEEPMode()` 进入 Sleep 模式
- **注意**：Sleep 模式下 SRAM（32KB+16KB）保持，LSI 保持运行

唤醒后动作 (`pm_wakeup_entry()`)：
- CPU 从 WFI/WFE 后继续执行（非冷启动）
- 判断唤醒源（KEYSCAN EXTI vs RTC）
- 恢复系统时钟（HSI 快速起振）
- 恢复外设（GPIO/KEYSCAN 已保持）
- 重新初始化 BLE 广播/连接
- 根据绑定状态决定进入配对态还是回连态

## 五、问题确认结果（基于芯片手册+原理图+国标）

> 以下结论基于对 `BARROT_BR1601A02_Datasheet_V1.5.pdf`、`BARROT_BR1601用户手册_V1.1.pdf`、`Vioce_Cat1_Remote_V1.0(3).pdf`（原理图）、`GY T 407-2024 机顶盒通用遥控技术要求和测量方法.pdf` 的交叉分析。

### 5.1 已确认项

| 问题 | 结论 | 依据 |
|------|------|------|
| 语音触发唤醒 | 仅按键触发（KEY15长按），无对端下发语音指令 | 用户确认 |
| CAT1 接收保持 | 关闭 UART TX，保持 UART RX 中断 | 用户确认 |

### 5.2 文档分析结果

#### ① 休眠模式选择：应使用 Sleep 模式而非 PD 模式

**数据手册关键数据**（Datasheet p5）：
- Sleep 模式（48KB RAM 保持）: **1.6μA @ 3V**
- Power Down 模式: **130nA**

**用户手册 PWR 章节关键对比**（用户手册 §3.2）：

| 特性 | Sleep 模式 | Power Down 模式 |
|------|-----------|----------------|
| CPU | 停 | 停（全部断电） |
| SRAM | **保持**（32KB SYS + 16KB） | **丢失** |
| HSE/HSI | 关闭 | 关闭 |
| LSE/LSI | **保持运行** | **关闭** |
| FLASH | 关闭 | 关闭 |
| 唤醒源 | EXTI（RTC + LPUART + **KEYSCAN** + 8个IO） | **仅 RESET 引脚 + WKUP1 引脚** |
| 唤醒后行为 | 从 WFI/WFE 后继续执行 | **从复位向量重新启动**（冷启动） |

**结论：使用 Sleep 模式，不使 用PD 模式。**

理由：
1. Sleep 模式 1.6μA ≪ 20μA 指标要求，余量充足
2. Sleep 模式 **支持 KEYSCAN EXTI 唤醒**，用户按键即可唤醒
3. Sleep 模式 **支持 RTC 定时唤醒**（LSI 仍在运行）
4. Sleep 模式 **SRAM 保持**，唤醒后无需重新初始化所有外设，延迟极低
5. PD 模式仅有 RESET/WKUP1 可唤醒，**KEYSCAN 不可唤醒**，且 **RTC 不可用**，无法实现"按键唤醒+RTC定时唤醒"的需求

---

#### ② RTC 时钟源：仅有 LSI（内部 32KHz RC），无 LSE

**原理图分析**（`Vioce_Cat1_Remote_V1.0(3).pdf`）：
- 芯片引脚 PB8 标注为 `PB8_KEY`（按键），PB9 标注为 `PB9_KEY`（按键）
- 这两个引脚同时也是 `X32K_IN` / `X32K_OUT`（LSE 晶振引脚）
- **板上未焊接 32.768KHz 晶振**，引脚复用为 KEYSCAN 输入
- 32MHz HSE 晶振（X1）已焊接

**代码印证**（`cfg_user.h`）：
```c
user_cfg user_env = {
    .lsc_type = LSCI_32000HZ,  // 使用内部 32KHz RC
};
```

**结论：RTC 时钟源为 LSI（内部 32KHz RC），无 LSE。**

影响：
- RTC 定时精度较低（±5%~10%），5s 定时实际约 4.5~5.5s
- **这不影响功能**，休眠唤醒对时间精度不敏感
- 代码中直接使用 `RTC_WKUPCLK_RTCCLK_DIV*` 配置 LSI 分频即可

---

#### ③ 连接参数切换对端兼容性：50ms 在国标范围内

**GY/T 407-2024 第 5.1.2.3 节明确要求**（规范 p4-5）：

| 参数 | 要求值 |
|------|--------|
| 连接间隔（工作态） | **5ms ~ 50ms** |
| 连接间隔（低时延） | 1ms ~ 5ms |
| 待机平均电流 | ≤ 65μA |
| 休眠平均电流 | ≤ 20μA |

**结论：待机态 50ms 连接间隔完全在国标要求范围内。**

- GY/T 407-2024 明确规定了 5ms~50ms 的连接间隔范围，合规 STB **必须接受**此范围内的参数更新请求
- 待机态使用 50ms（上限）形成与工作态 10ms 的明显功耗梯度，符合规范设计意图
- 低时延模式（1ms~5ms）规范附录 C.3 已预留框架，后续可扩展

---

#### ⑥ 唤醒延迟：Sleep 模式延迟极低

**基于 Sleep 模式（非 PD）的分析**：

| 阶段 | 耗时估算 | 说明 |
|------|----------|------|
| EXTI 唤醒 + 时钟恢复 | <100μs | HSI 内部 RC 起振极快 |
| 外设恢复（GPIO/KEYSCAN） | <1ms | SRAM 保持，只需恢复寄存器 |
| BLE 栈恢复 | 待实测 | SRAM 保持，BLE 状态机可快速恢复 |
| 广播启动 → STB 连接 | 1~2 个扫描周期 | 取决于 STB 扫描参数 |

**结论：由于 SRAM 保持，唤醒延迟预估 <10ms（不含 STB 连接时间），用户无感知。**

> 与 PD 模式对比：PD 模式需要从复位向量重新启动，重新初始化 PLL/FLASH/BLE栈，延迟可能达数百 ms。

---

### 5.3 方案调整汇总

| 原方案 | 调整后 | 原因 |
|--------|--------|------|
| PD 模式实现休眠态 | **Sleep 模式** | 1.6μA 满足 ≤20μA；支持 KEYSCAN + RTC 唤醒；SRAM 保持 |
| 唤醒后重新初始化 BLE 栈 | **快速恢复**（重置 BLE 状态，不需完整 init） | SRAM 保持，仅需恢复 BLE 活动 |
| 假设可能无 LSE | **确认只有 LSI** | 原理图 PB8/PB9 用作按键，无外部晶振 |
| 担心对端不接受 50ms | **国标明确要求 5~50ms** | GY/T 407-2024 §5.1.2.3 |

## 七、风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Sleep 模式 SRAM 仅保持 32KB+16KB | 大数组可能丢失 | 将休眠期间需要保持的关键状态放入 SYS SRAM 保持区 |
| 待机参数对端不支持 | 连接断开 | 50ms 在国标范围内；若个别 STB 拒绝，逐步降级到 40ms/lat80 |
| 待机功耗不达标 | ≤65μA 指标不通过 | 逐模块关闭外设测试功耗（ADC/MICBIAS/LED/CAT1），找出主要耗电源 |
| 回连超时进入休眠 | 用户需要按键才能唤醒 | RTC 每 5s 唤醒检查，可快速恢复广播 |
| LSI 精度低导致 RTC 定时偏差 | 唤醒时间不准 | 对功耗管理无实质影响，±10% 误差可接受 |
