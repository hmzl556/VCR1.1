# 06 OTA 升级（师弟写）— 通俗讲解笔记

> 代码：[bleuart/cat1/cat1/OTA/](bleuart/cat1/cat1/OTA/)（udp_ota.c 状态机 / ota_frame.c 组帧 / udp_bootload.c Flash 管理 / ota_crc.c / flash_layout.h 分区）+ [引导程序-bootloader/](引导程序-bootloader/)（16KB Boot 工程）
> 协议依据：doc/OTA升级协议文档-0618更新.pdf（已提取文本存 doc/简历准备/_OTA协议提取.txt）

## 一句话定位

遥控器固件通过 Cat.1 UDP **远程升级**：新固件先下载到备份区（APP2），校验无误后写升级标志并复位，16KB Bootloader 把备份区复制到运行区（APP1）完成切换——**A/B 双分区 + 断点续传 + 升级失败不砖**。

## 通俗类比：装修不停业 + 验收后换房

```
下载阶段: 新房子(APP2)先装修好，旧房子(APP1)照常营业 —— 下载不影响运行
验收阶段: 逐包验货(CRC) + 全部装完后整体验收(整包校验和)
交接阶段: 写"可以搬家了"的纸条(升级标志 0x12345678) → 复位
搬家阶段: 门卫(Bootloader)看到纸条 → 把新房内容复制进旧房 → 撕掉纸条 → 开门营业
```

## 完整升级流程（八步）

1. **触发**：遥控器正常上报 Tag01 状态包 → 云端 Tag11 回执里带**新版本号+总包数**；
2. **版本判断**：服务器版本 < 本地 → **拒绝降级**；相同 → 跳过；更高 → 开始升级；
3. **断点续传**：读 Flash checkpoint（magic 'OTPH'）——版本+总包数一致 → 从 written_seq+1 续传（**不重新擦 APP2**）；
4. **下载（严格一问一答）**：发 `req_seq=N` → 收第 N 片 → 写 Flash → 发 `req_seq=N+1`。每片校验：序号范围/去重（收到已写片忽略）/片长 512/地址落在 APP2/序号与地址对应/首片额外校验版本与程序起止；
5. **写 Flash**：512B 缓冲按 **128B 分段写**，每段写完 **pump 一下 UART**（Qflash 写入关中断期间不能丢模组数据——这就是"Flash 擦写与 UART 实时性共存"的解法）；
6. **完成**：最后一片写完 → 发 req_seq=total+1 → **本地整包校验**（累加和比对）→ 一致 → 写 BOOTLOAD_PARA（prog_success_flag=0x12345678）→ 清 checkpoint → 复位；
7. **Bootloader**（上电先跑，16KB）：读 OTA 配置扇区 → 标志有效 → **APP2 逐 512B 复制到 APP1**（失败重试 10 次）→ 擦除配置扇区（清标志）→ 写完成 marker → 跳转 APP1；
8. **新 APP 启动**：读到 marker → **LED1 闪 3 秒**表示升级成功 → 清 marker。

## Flash 分区（硬件岗必背，和 BLE 绑定/云策略连成一片）

```
0x01000000  Bootloader   16KB   上电先跑（"门卫"，永不升级）
0x01004000  APP1         200KB  运行区
0x01036000  APP2         200KB  备份区（OTA 下载目标）
0x01068000  OTA 配置     4KB    升级标志 + 完成 marker + 断点 checkpoint
0x01069000  BLE 绑定     4KB    配对信息（三种连接方式笔记里就是它）
0x0106A000  云策略       4KB    按键采集/上报间隔
```

## 可靠性设计（面试重点，逐个都能展开）

1. **双校验**：每片帧 CRC-8（0x5D 多项式，覆盖控制域~数据域）+ 整包累加和（与服务器首包下发的校验字比对）——片级防传错、包级防漏防多；
2. **升级不砖的四道防线**：Boot 区永不升级；下载写在 APP2 不影响运行；复制失败**保留标志下次上电重试**；整包校验失败直接中止（旧固件照跑）；
3. **断点续传**：每片写完同步 checkpoint 到 Flash；下载中断（断网/断电）后 Tag11 重新触发时从断点继续；
4. **PAUSE/RESUME 机制**：单片连续 5 次超时/无进度 10s → PAUSE（写断点）→ 10s 退避 → 自动 RESUME 续传——防止网络差时死循环空转；
5. **OTA 会话隔离**（贯穿全系统）：会话期间停广播、停语音、CAT1 拒绝业务数据、组合键/工厂复位忽略、**PM 状态机拒绝进待机/休眠**（udp_ota_session_busy 遍布各模块）、已连接时保持 HID 键控可用；
6. **降级拒绝**：服务器版本比本地低直接忽略，防误回退。

## 协议帧（0x41，走 8889 端口，裸 UDP 无 AES）

- 下行：`0x41` + 长度(BCD) + 控制码 0x03 + 地址域(MAC BCD) + AFN 0x60 + 总包数/报序号/程序起止地址/新版本/程序校验字/本包地址/长度512/代码 + CRC-8 + `0x16`；
- 上行：`0x41` + 长度 + 0x13 + 地址域 + AFN 0x61 + 总包数/请求序号/请求地址/新版本/**状态**(0正常/1异常/2校验错误) + CRC + `0x16`；
- 一问一答：终端每片**主动索要**，服务器按请求下发——流控由终端掌握，天然抗拥塞。

## 面试自测题

1. 为什么用 A/B 双分区而不是直接覆盖 APP1？（升级过程不影响运行；中断可恢复）
2. 升级到一半断电怎么办？（checkpoint 断点续传；Boot 复制重试；标志保留）
3. 怎么保证永远不会变砖？（Boot 不升级 + APP2 备份 + 校验 + 标志时序）
4. 一问一答和服务器主动推流的取舍？
5. 两种 CRC 各管什么？0x5D 多项式是哪来的（协议附录 A 指定）？
6. Flash 写入时 UART 数据怎么不丢？（128B 分段 + pump +ECSONMI）
7. 为什么先写升级标志再复位？标志的时序？
8. checkpoint 什么时候写、什么时候清？
9. Bootloader 怎么知道该不该复制？复制失败会怎样？
10. 升级期间遥控器还能用吗？（HID 保持、语音/广播/CAT1 业务暂停——为什么这样设计）
11. 为什么拒绝降级？
12. 升级成功用户怎么知道？（LED1 3 秒指示 + marker）

## 与硬件岗的关联点

- **Flash 分区规划**：6 个区各司其职、互不重叠（BLE 绑定地址的变迁故事也在这条线上）；
- Qflash 擦写特性：整扇区擦除、写入时序、擦写期间关中断对系统实时性的影响；
- 复位流程：NVIC_SystemReset 后 Boot → APP 的跳转机制（向量表重定位）；
- 升级指示 LED 的用户体验设计。
