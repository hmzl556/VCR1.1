# 蓝牙语音遥控器功耗优化方案

> 面向"功耗系统工程师"面试的系统性方案文档。代码依据：bleuart/pmu/（pm_state/pm_standby/pm_sleep）、bleuart/cat1/cat1/（rc_cat1_bridge/heartbeat/remote_reports）、main.c / task_ble.c。
> 所有数字均为实测值（功耗仪：量程 0–999mA，精度 0.01µA）。

## 0. 一句话总览

整机功耗由"**睡眠机制选型 + 板级漏电治理 + 外设电源策略**"三根柱子支撑：睡眠机制决定功耗下限（芯片睡眠模式的固有电流），板级漏电决定实际值（漏电不受软件控制），外设电源策略决定占空比（CAT1 用与不用差 7mA）。三者缺一不可——只用睡眠函数而不管板级，实测会在 50µA 打转；只清漏电而不做按需上电，CAT1 常开会吃掉 7mA。

## 1. 功耗指标与预算（国标 GY/T 407-2024 要求 vs 实测）

| 状态 | 国标限值 | 实测 | 余量 |
|---|---|---|---|
| 按键（工作+BLE 发射） | 10mA | **2.51mA** | 4 倍 |
| 语音（工作+BLE 音频流） | 15mA | **5.39mA** | 2.8 倍 |
| 待机态（保持 BLE 连接） | 65µA | **<10µA** | 6.5 倍+ |
| 休眠态（无连接） | 20µA | **<10µA** | 2 倍+ |

功耗预算方法：先按国标定各状态上限 → 再按硬件主体分解（SoC 基础电流 / BLE 活动电流 / CAT1 占空比 / 语音链路 / 板级漏电）→ 实测数据反推各主体实际占比 → 针对超标项逐层优化。**待机/休眠是优化主战场**（µA 级，占产品全生命周期 >95% 时间），按键/语音是峰值状态（mA 级但占时 <5%），优化优先级按"状态占比 × 超标倍数"排序。

## 2. 系统功耗架构（六大功耗主体）

```
总电流 = SoC 基础(睡眠模式) + BLE 活动(广播/连接事件) + CAT1(占空比×7mA)
       + 语音链路(ADC/PGA/MICBIAS, 仅语音时) + LED + 板级漏电(工艺/引脚)
```

- **SoC 基础**：由睡眠模式决定——br_sleep 深睡 ~3µA；
- **BLE 活动**：广播 ~mA 级（20ms 间隔）；连接事件唤醒的平均电流取决于连接参数（间隔/延迟数）；
- **CAT1**：常开 ≈7mA（无业务也如此）→ 必须按需上电，否则任何低功耗设计都被它抹平；
- **语音链路**：MICBIAS/PGA/AUDIOPLL 只在语音会话期间开；
- **板级漏电**：引脚配置（上拉电流、ESD 灌电）+ 工艺污染（助焊剂/手汗）——**软件测不出来的部分**。

## 3. 睡眠机制选型（核心决策，面试必问）

芯片提供三种睡眠层次，逐层对比后才定方案：

| 方案 | 能否保连接 | 功耗 | 问题 | 结论 |
|---|---|---|---|---|
| SDK standby 模式 | ✗ 不能 | 1mA+ | 国标强制待机态保持 BLE 连接 | 否决 |
| 裸 WFI（PWR_EnterSLEEPMode） | 不感知 modem | ~µA | **BLE modem 有周期性校准事件（1-2s），裸 WFI 被唤醒后栈/modem 状态不一致 → 打印乱码 + 复位（实测睡后 1-2s 必重启）** | 否决 |
| **br_sleep()（SDK modem 感知深睡）** | ✓ 可以 | 深睡 ~3µA | 连接事件/校准事件会周期性唤醒（"噪音唤醒"），需要配套过滤 | **采用** |

**最终架构：待机态与休眠态统一使用 br_sleep()，差异只在"是否保持连接"**：
- 待机态：**保持连接**，br_sleep 在连接事件间隙深睡；代价是连接事件周期性唤醒（50ms 间隔 + latency 100，最长 5s 不监听）；
- 休眠态：**主动断连**（只断连不擦绑定），断连后 br_sleep 无需维持连接 → 无 50ms 连接事件唤醒，深睡电流与待机相当（~3µA）。若保持连接，实测平均 20+µA，**不满足休眠态 <20µA 的国标要求**——这是"断连换功耗"的直接依据。

**为什么裸 WFI 不行（面试展开点）**：BLE modem 不是纯软件外设，它有周期性射频校准（SDK 管理，约 1-2s）。裸 WFI 只停 CPU、不管 modem 状态机，被校准事件唤醒后两者不同步 → 崩溃。br_sleep 是 SDK 提供的"modem 感知"睡眠入口，醒来后时钟由 SDK 恢复、状态一致。**选型结论：睡眠原语必须与无线子系统联动，这是带射频 SoC 功耗设计的关键约束。**

## 4. 待机态方案（保持连接的低功耗：1mA+ → 500µA → <10µA）

**目标**：保持 BLE 连接（国标强制）的前提下把电流压到 65µA 以下。

**三层手段**（按贡献排序）：

1. **睡眠机制层**：工作态持睡眠锁 → br_sleep 只进浅睡（保按键响应延迟）；待机态放锁 → 连接事件间隙深睡。**tickless**：删掉 8ms SDK 定时器（FreeRTOS tick 注入源），否则 br_sleep 被每 8ms 唤醒一次（125Hz 噪音），永远睡不深；
2. **外设层**：
   - 时钟门控：关 SPI1/2、TIM1、USART1、WWDG、CRC 外设时钟（RCC 现场保存/恢复），外设静止且寄存器保留，恢复免初始化；
   - 关 USART2（CAT1 串口）、关语音链路（MICBIAS/PGA/AUDIOPLL 全关）、灭 LED；
3. **引脚层（逐引脚电流审计，500µA→<10µA 的关键）**：功耗在 400~600µA 间跳动 → 典型引脚漏电特征 → 对照原理图逐脚核算电平/上下拉/外部网络：
   - **PB4**（USART2 TX → 未上电 CAT1 的 LTE_RXD）：空闲高电平经模组 ESD 钳位二极管灌入其 VBAT 轨 → 模组半上电振荡，**500µA 主犯**。修复：关 USART2 后配推挽输出低；
   - **PB6**（VLTE 分压检测）：内部上拉经外接 4.7K 对地白耗 ~74µA → 模拟输入无上拉；
   - **PB5**：外部已有 10K 上拉、内部上拉冗余，CAT1 放电窗口 Q3 微导通时多耗 ~80µA → 浮空输入；
   - **PB11/12/13**（麦克风偏置）：上拉会给麦供电 → 模拟输入断电；
   - 未用引脚全部模拟输入，消除浮空输入振荡电流。

**Ble 参数层**：连接参数从工作态 10ms/latency 40 切换到 50ms/latency 100（最长 5s 不监听），监管超时按 (1+latency)×interval×2 校验（10.1s < 12s 合规）。参数切换由 le_conn_update 动态完成，**不断连、无感知**。

**超时参数（定版）**：工作→待机 30s 无活动；待机→休眠累计 90s 无活动。

## 5. 休眠态方案（断连深睡：50~60µA 不稳 → <10µA）

**目标**：无连接状态（20µA 限值）。两个问题先后解决：

### 5.1 板级漏电（工艺问题，软件手段穷尽后定位）
- 现象：实测 50~60µA 且读数极不稳定；
- 软件手段穷尽：停广播、外设全关、清 pending 中断、引脚低功耗配置——电流纹丝不动；
- 转折：**洗板水对照实验**——清洗电路板后 <10µA，问题在板子；
- 根因：焊接残留助焊剂/手汗的离子污染形成板面泄漏通路（漏电对温湿度敏感 → 读数跳动）；
- 量产方案：导入三防漆工艺。

### 5.2 睡眠机制重设计（断连 + 噪音唤醒过滤）
- **主动断连**：进入休眠先 le_conn_destory（只断连不擦绑定），唤醒后走回连广播重建连接。依据：保持连接的 br_sleep 实测平均 20+µA 不达标，断连后 ~3µA；
- **栈复用**：保持 bleAdvStat=0xa6，唤醒后**复用现有 BLE 栈**重启广播。若重建栈 = 在已有栈上二次初始化 → 二次 malloc → 堆耗尽（堆仅 10KB）→ HardFault（实测每次按键唤醒都硬复位一次；冷启动正常因为堆是全新的——**问题只在唤醒路径**）；
- **br_sleep 循环 + 噪音唤醒过滤**：modem 周期校准（1-2s）会让 br_sleep 自行返回——这是噪音不是用户唤醒 → 清残留中断继续睡；**只有按键（key_receive/EXTI13）或心跳到期才退出循环**。每次返回后 cs_schedule() 服务栈事件（否则事件堆积崩溃）；
- **统一暂停 8ms tick 定时器**：回连/配对态直接进休眠时定时器还在跑 → br_sleep 被每 8ms 叫醒（125Hz 噪音），实测 ~2000 次噪音唤醒后必崩。待机入口已暂停过，此处幂等；
- IWDG 配合：深睡期间 LSI 停止 → 看门狗冻结不误复位；睡前喂狗换取唤醒后 10s 宽限；
- SWD 保护：GPIOA PA4/PA5 保持调试功能（改模拟后调试器连不上——调试教训）。

## 6. CAT1 电源策略（按需上电：7mA → 接近 0）

**问题**：Cat.1 模组只要上电、不发数据也有 ~7mA 基带功耗；AT 指令自带 PSM 低功耗模式，但 PSM 需要**基站侧配合**（周期 TAU 协商），现网支持不稳定。

**方案：硬开关按需上电**——LTE_EN（PB2）经 MOS 管控制模组 VBAT 电源，策略为"**事务完成即断电、有数据才上电**"：

- **上电触发源**（三个，任一满足）：① 有 RC-TRANS 数据待上报（STB 经 BLE 下发）；② OTA 会话；③ 心跳到期；
- **上电流程**：LTE_EN 拉高 → 2s boot 等待（模组启动）→ 22 阶段 AT setup（含 CGATT 附着轮询、CCLK 对时、ECSOCR 建 UDP socket）→ 业务收发 → Tag11 回执；
- **断电判定**：UDP 就绪 + 无 OTA + 无待发数据 + 队列空 + modem 空闲 → 立刻断电；
- **失败退避改断电**：连续 3 次发送失败 / 连续 3 次上行后无下行 → 直接断电重启（比软件重建更省电、更彻底）；
- **断电细节**：PB4（USART2 TX）配输出低——否则 TX 空闲高电平经肖特基二极管/ESD 二极管给未上电模组充电，唤醒后放电窗口把功耗拉回 500µA；
- **效果**：CAT1 平均功耗 = 7mA × 占空比（一次上报约十几秒/周期），心跳周期 30min 时占比可忽略。

**为什么不用 PSM（面试展开点）**：PSM 是模组内协议栈级休眠（深度睡眠 + 周期唤醒监听寻呼），功耗 µA 级但不为 0，且依赖基站 TAU 协商——现网基站配置不一，实测不稳定。硬件断电是确定性手段：功耗**严格为 0**、不依赖网络侧。代价是每次上电要付 2s boot + setup 的时延和电流——所以策略设计为"业务驱动、批处理、事务结束即断电"。

## 7. 心跳机制（可达性与功耗的折中，新增）

**需求矛盾**：服务器需要定期知道遥控器"活着"（并借此下发参数/OTA 版本），但遥控器为了省电大部分时间在深睡/断电——**可达性（服务器能触达）与功耗天然对立**。

**方案**：遥控器主动周期报活（Tag0x0A：操作时间 BCD6 + SIM 卡号 BCD10 + 电量 1B），周期由服务器 Tag11 响应数据 ID6 热更新下发（秒，0=关闭；出厂默认关闭，测试期 1800s）。

**三态集成**（体现"功耗优先、心跳不打断深睡"）：
- 工作态：主循环每圈检查，到期直接组帧入队 + CAT1 上电；
- 待机态：br_sleep 连接事件唤醒（~5s）时检查，到期切回工作态由工作路径触发；
- 休眠态：**复用噪音唤醒**（~1-2s 一次）检查，到期退出深睡循环——即"定时唤醒 MCU"，**不额外增加唤醒源和功耗**，精度 ±2s 对分钟级周期无影响；
- 忙时挂起补发：OTA/CAT1 业务忙时不打断，业务结束立刻补发（不丢本次心跳）；
- 计时：app_now_ms 单调毫秒计数，br_sleep 期间由 SDK 做睡眠补偿持续推进（待机 90s 超时已验证）；32 位回绕安全（有符号差值判断）。

**设计要点（面试金句）**："心跳的功耗成本 = 唤醒次数 × 单次唤醒能量，而不是持续电流。把心跳检查挂在已有的唤醒点上（连接事件/噪音唤醒），边际成本接近零。"

## 8. 板级漏电治理（工艺层面）

- 引脚级：逐脚审计（见待机态方案），配置引脚 = 管理电流路径；
- 板级：助焊剂/手汗离子污染 → 洗板水对照实验定位 → 量产三防漆工艺；
- 器件级：ESD 钳位二极管对未上电器件的灌电路径（PB4 案例）——**"未上电器件的 IO 不能给高电平"**。

## 9. 关键工程问题档案（根因分析，面试可逐个展开）

| # | 现象 | 根因 | 措施 |
|---|---|---|---|
| 1 | 待机 500µA 且 400~600µA 跳动 | PB4 空闲高电平经 CAT1 ESD 二极管灌入未上电模组 VBAT | 关 USART2 + PB4 输出低 |
| 2 | 休眠 50~60µA 不稳 | 助焊剂/手汗板面离子污染 | 洗板水对照实验定位，量产三防漆 |
| 3 | 裸 WFI 休眠 1-2s 后必重启 | modem 周期校准唤醒后栈/modem 状态不一致 | 改用 br_sleep（modem 感知） |
| 4 | 回连态直接进休眠十几秒后崩 | 8ms tick 定时器未停 → 125Hz 噪音唤醒，~2000 次后崩溃 | 进休眠统一 sdk_timer_pause |
| 5 | 每次按键唤醒都 HardFault | 唤醒路径重建 BLE 栈 → 二次 malloc 堆耗尽（堆 10KB） | 保持 bleAdvStat，复用现有栈 |

## 10. 功耗测试方法

- 仪器：专用功耗仪（量程 0–999mA，精度 0.01µA），串联供电回路；
- 方法：每状态各测稳态电流 + 观察波动范围（跳动 = 漏电特征）；动态事件（按键/语音/上报）测峰值与持续时间 → 算状态占空比 → 估算整机月均功耗；
- 对照实验：洗板水清洗前后对比——**软件手段穷尽后的板级验证方法**；
- 时域视角：不只测稳态，还测"状态切换瞬间"（如 STANDBY→SLEEP 时调节器方向反转、CAT1 放电窗口）——多个问题只出现在切换窗口，稳态测不出来。

## 11. 面试高频问答（功耗系统工程师视角）

1. **你们的功耗是怎么分解和预算的？** → 第 1、2 节：国标定上限 → 按硬件主体分解 → 按"状态占比×超标倍数"排优先级。
2. **为什么选 br_sleep 而不是裸 WFI / standby？** → 第 3 节对比表 + modem 感知约束。
3. **待机态怎么做到既保连接又 <10µA？** → 第 4 节三层手段 + 连接参数分级 + 逐脚审计。
4. **休眠态为什么要主动断连？** → 保持连接实测 20+µA 不达标；断连后 ~3µA；唤醒走回连（秒级）可接受。
5. **CAT1 为什么不用 PSM 而用硬断电？** → PSM 依赖基站不稳定；硬断电功耗严格为 0、确定性；代价是 boot 时延，用"业务驱动+批处理"吸收。
6. **心跳怎么做到不破坏低功耗？** → 第 7 节：挂接已有唤醒点，边际成本≈0。
7. **<10µA 用什么测的？怎么保证精度？** → 功耗仪量程/精度 + 稳态/波动/切换窗口三视角测量。
8. **平均功耗怎么算？** → 各状态电流 × 时间占比加权；说明峰值与平均的关系（遥控器 95%+ 时间在待机/休眠，所以 µA 级优化价值远大于 mA 级）。
9. **睡眠期间时间怎么走？** → app_now_ms 由 SDK 在 br_sleep 期间做睡眠补偿，32 位回绕安全。
10. **功耗优化和功能冲突时怎么取舍？** → 三个案例：待机不断连（延迟换功耗的下限）、休眠断连（功耗换唤醒延迟）、心跳周期（可达性换功耗，由服务器动态调整）。
