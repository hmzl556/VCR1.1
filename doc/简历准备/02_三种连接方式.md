# 02 BLE 配对 / 回连 / 唤醒三种连接方式 — 复盘笔记

> 代码：[ble_gap.c](bleuart/src/ble_gap.c)（连接管理+配对信息持久化）、[ble_adv.c](bleuart/src/ble_adv.c)（三种广播包）、[combo_key.c](bleuart/src/combo_key.c)（配对/解配组合键）、[task_keyscan.c](bleuart/src/task_keyscan.c)（电源键触发唤醒广播）

## 一句话定位

用**三种不同的广播包**覆盖遥控器的三个场景：新设备**配对**（可发现广播）、老设备**回连**（不可发现广播+白名单）、机顶盒待机**唤醒**（定制唤醒包，带双方地址）。配合绑定信息 Flash 持久化，实现"一次配对、上电自动回连"，全程对标国标 GY/T 407-2024。

## 一、三种广播对比

| | 配对广播（类型1） | 回连广播（类型2） | 唤醒广播 |
|---|---|---|---|
| 触发 | 组合键 KEY14+KEY10 长按 3s；上电无绑定（测试配置） | 上电有绑定 / 断连 / 休眠唤醒 | 回连态下按电源键 KEY1 |
| 可发现性 | 可发现（Flags 0x05 = Limited Discoverable） | 不可发现（Flags 0x04，不响应扫描） | 不可发现 |
| 广播数据 | UUID + 指示 0x00 + 基础能力 0x08 + 发射功率 0x02 | UUID + 指示 0x02 | **UUID 反转** + 指示 0x15 + 源/目标地址 |
| 扫描响应 | Appearance + 设备名 "GehuaRemote" | 无 | HID UUID |
| 目的 | 任何 STB 都能发现并配对 | 只有绑定的 STB 能回连 | 唤醒待机的 STB |
| 超时 | 30s → SLEEP | 60s → SLEEP | 发完即止 |

## 二、核心机制

### 1. 广播包格式（AD 结构 + 国标字段）
- BLE 广播数据 = 一串 AD 结构 `[长度][类型][数据]`：Flags(0x01)、16-bit HID UUID 0x1812(0x03)、Service Data-128bit UUID(0x21)、Appearance(0x19)、Local Name(0x09)；
- 128-bit UUID 是"通用遥控终端服务"（GY/T 407-2024 附录 A），**指示信息字节**区分广播类型 1/2（附录 C.1），发射功率 0x02 表示 ≥2dBm（条款 5.1.2.3），广播间隔 20ms（附录 C.2）。

### 2. 配对流程（Just Works）
- IO 能力 NOINPUTNOOUTPUT → 自动接受配对请求（Just Works，无 PIN 交互）；
- bondable + Security Mode 1 Level 2（加密不强制 MITM，兼容大多数机顶盒）；
- 配对完成（GAP_EV_PEER_BONDED）→ 保存到 Flash @0x01069000：头部（magic "BOND"/version/data_sz/**对端身份地址**/checksum）+ 绑定数据（LTK/IRK 等）。

### 3. 回连（绑定持久化 + 白名单）
- 上电时读 Flash → magic/checksum 校验 → `peer_recover()` 恢复到 RAM → STB 看到广播后**基于之前的绑定自动重连，无需重新配对**；
- 白名单：`le_wl_clear()` + `le_wl_add(对端地址)` → 回连广播只允许已绑定 STB 接入；
- 断连时 `pm_notify_disconnected()`：有绑定 → RECONNECTING → 重启回连广播（解配中/OTA 会话中跳过）；
- 初始化时序坑：GATT 服务必须在 `ble_gap_init()`（内部 peer_recover）**之前**创建，协议栈才能追踪 GATT 变更、向 STB 发 Service Changed（见 main.c 注释）。

### 4. 唤醒（唤醒待机的 STB）
- 场景：STB 待机时不扫描普通广播，遥控器在回连态按电源键 KEY1 → 切唤醒广播；
- **UUID 反转字节序**：STB 扫描过滤器不匹配正常服务 UUID，专用于识别唤醒包，避免把普通广播误判为唤醒信号；
- 指示字节 0x15：bit0-1=类型2，bit2=含地址，bit4=唤醒标志；
- 携带双方 MAC 低 3 字节：源=遥控器（local_bd），目标=STB（从 Flash 绑定头部偏移 13 处读取）；
- 发完等 20ms（一个广播间隔）确保包已发出。

### 5. 连接成功后的善后（ble_gap_connected）
1. 停广播（国标附录 C.2）；
2. `pm_notify_connected()` → WORKING；
3. **延迟 3s** 再发起连接参数更新（刚连接立即更新容易失败）；
4. **CCCD 自旋重试**：每 500ms 查 STB 是否使能 CCCD，最多 6 次（3s），没使能就 `hid_kbd_force_cccd_enable()`——HID 数据要发出去必须 STB 使能 notify；
5. MTU 交换 515（大包语音数据用）。

### 6. 连接参数管理（与低功耗联动，"last good params" 模式）
- 默认工作参数 10ms / latency 40 / timeout 800（国标 5.1.2.3 + 附录 C.2）；
- 对端请求参数时**范围校验**（5~50ms、latency 40~100），越界回退最近一次合规参数；
- 更新成功且合规才保存为 last good（持久化默认关闭，防 Flash 频繁擦写损耗）；
- 低时延模式（国标附录 C.3）预留了框架。

## 三、组合键状态机（combo_key.c）

- 通用状态：IDLE → HOLDING（双键同按计时 3s，提前松手取消）→ TRIGGERED；
- **配对键** KEY14+KEY10（旧板子 KEY14+KEY4）：先 `ble_gap_clear_bonding_info()` 清旧绑定（**清了才能被发现**）→ 置 g_pairing_active → 转 PAIRING 态 + 可发现广播 → LED2 200ms 闪；
- **解配键** KEY3+KEY9（旧板子 KEY4+KEY9）：清绑定（内部先断连）→ 等断连完成且 LED1 至少亮 2s（或 30s 安全网超时）→ 转 SLEEP；
- 与工厂复位（KEY6+KEY14）互斥：combo_key 活跃时工厂复位不响应，反之亦然；
- OTA 会话期间组合键只检测不执行。

## 四、几个值得讲的坑

1. **清除绑定不能整扇区擦除**：绑定扇区 0x01069000 在固件代码区（与 BLE 协议栈代码重叠），直接 Erase_Sector 会毁掉协议栈 → 改为写 0 到 magic 字段使其失效；
2. **断连回调顺序敏感**：`pm_notify_disconnected()` 必须在 `g_peer` 清零之前调用（内部要查 peer_bonded_count）；
3. **断连善后分两段**：GAP 回调里只置 pending 标志，真正清理（keyscan/hid/rc_trans/bas 复位 + 重启广播）放到主循环 `ble_gap_process_disconnect_pending()`，避免在协议栈回调上下文里做重活；
4. **绑定存储地址的变迁**（注释里可见迭代痕迹）：APP1 末尾 → APP2 末尾扇区 → 最终 OTA 配置扇区 +4KB（0x01069000），与固件/OTA 区域均不重叠——Flash 分区规划能力；
5. 唤醒广播的 UUID 反转是刻意设计，不是笔误——STB 侧靠它区分"唤醒包"和"普通广播包"。

## 六、与硬件岗的关联点

- 广播发射功率/2.4GHz 天线（原理图射频部分，面试可提 PCB 天线匹配）；
- Flash 分区规划：固件区 / OTA 区 / 绑定信息区 / OTA 配置区不重叠；
- 按键 → EXTI → 广播 → STB 的整条硬件唤醒链路；
- 广播间隔 20ms 与功耗的权衡（广播比连接更耗电——30/60s 超时进休眠就是为这个）。
