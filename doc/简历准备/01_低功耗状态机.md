# 01 低功耗状态机与功耗优化 — 复盘笔记

> 代码：[bleuart/pmu/](bleuart/pmu/)（pm_state.c / pm_sleep.c / pm_standby.c / pm_config.h），入口 [main.c](bleuart/src/main.c)、[task_ble.c](bleuart/src/task_ble.c)

## 一句话定位

给遥控器设计了一个**六级功耗状态机**，让设备在用户不操作时逐级"降档"：全速工作（10ms 连接间隔）→ 待机（50ms 间隔 + CPU 事件间深睡）→ 休眠（WFI 微安级），并把每一级"关什么、怎么关、每根引脚的电流走向"都抠了一遍。最终把休眠电流压到 µA 级，靠的不是某一个大招，而是从系统到引脚的逐层审计。

## 一、状态机全景

```
上电
 ├─ 无绑定 → SILENT ──60s无按键──→ SLEEP
 │              │KEY14+KEY3 组合键
 │              ↓
 │           PAIRING ──30s无连接──→ SLEEP
 │              │连接成功
 │              ↓
 └─ 有绑定 → RECONNECTING ──60s无连接──→ SLEEP
                │连接成功
                ↓
             WORKING ──空闲30s──→ STANDBY ──空闲90s──→ SLEEP
                ↑                    │
                └─────有活动(按键)────┘

断连：WORKING/STANDBY ─有绑定→ RECONNECTING，无绑定→ PAIRING
唤醒：SLEEP ─按键→ 有绑定→RECONNECTING，无绑定→SILENT
```

| 状态 | BLE 行为 | 硬件动作 | 功耗等级 |
|---|---|---|---|
| WORKING 工作态 | 已连接，10ms 间隔 + latency 40 | 全功能 | 高 |
| STANDBY 待机态 | 已连接，50ms 间隔 + latency 100（最长 5s 不监听） | 关外设时钟/串口/LED/语音，CPU 事件间 br_sleep 深睡 | 中低 |
| SILENT 静默态 | CPU 运行但不广播，等组合键 | 仅 LED 指示 | 中 |
| PAIRING 配对态 | 可发现可连接广播（30s 窗口） | 广播耗电 | 中 |
| RECONNECTING 回连态 | 不可发现可连接广播（60s 窗口） | 广播耗电 | 中 |
| SLEEP 休眠态 | 无连接无广播 | 全外设关，WFI，仅按键 EXTI 唤醒 | µA 级 |

**设计哲学**：功耗梯度 = 响应延迟的代价。
- 工作→待机**不断连**，只拉长连接参数 → 按键响应无感（几十 ms），用户体验无损；
- 待机→休眠才断连 → 唤醒要重建广播+回连（秒级延迟），所以只在"长时间没人用"时才走；
- 静默态的意义：没绑定过的遥控器不发任何广播 → 省电 + 不被陌生设备扫描/连接。

## 二、省电手段分层（简历金句结构：从系统到引脚五个层面）

| 层次 | 手段 | 代码位置 |
|---|---|---|
| 系统层 | 六级状态机 + 独立超时参数 | pm_state.c / pm_config.h |
| BLE 层 | 连接参数切换 10ms/40 → 50ms/100，监管超时 (1+latency)×interval×2 校验 | pm_standby.c |
| CPU 层 | 待机态事件间 br_sleep() 深睡（睡眠锁控制深度）；休眠态 WFI | pm_standby.c / pm_sleep.c |
| 外设层 | 时钟门控 SPI1/2/TIM1/USART1/WWDG/CRC；关 USART2/语音/LED；停 8ms tick 定时器 | pm_standby.c |
| 引脚层 | 逐脚电平/模式/上下拉审计（对照原理图） | pm_standby.c / pm_sleep.c |

## 三、硬件调试故事（面试背熟，每个都能讲 3 分钟）

### 故事 1：PB4 灌电流 500µA（最有价值的一个）
- **现象**：休眠期实测 ~500µA 异常电流，且电流跳动、手摸敏感。
- **根因**：USART2 TX（PB4）空闲为高电平 3.3V，直连**未上电** CAT1 模组的 LTE_RXD。CMOS 芯片每个 IO 对电源轨都有 ESD 钳位二极管，"IO 有电压、VDD 没电压"时二极管正向导通 → 3.3V 灌进模组 VBAT 轨 → 模组"半上电"振荡。
- **修复**：进低功耗前先禁 USART2，再把 PB4 配成推挽输出低。
- **面试点**：ESD 二极管结构、硬件铁律"未上电设备的 IO 不能给高电平"、会沿信号路径查泄漏电流。

### 故事 2：逐脚审计——上拉电阻白耗电
对照原理图逐脚核算（[pm_standby.c:113-163](bleuart/pmu/src/pm_standby.c#L113-L163)）：
- PB6（VLTE 分压检测，外接 20K/4.7K 分压对地）：内部上拉会白耗 ~74µA → 改**模拟输入无上拉**；
- PB5：外部已有 10K 上拉，内部上拉冗余，CAT1 放电窗口 Q3 微导通时多耗 ~80µA → **浮空输入**；
- PB11/12/13（麦克风偏置）：上拉会经 R23/R24/R25 给麦供电 → **模拟输入断电**；
- 未用引脚全部模拟输入（浮空输入的施密特触发器会振荡耗电）。
- **面试点**：会算 V/R 电流、懂 GPIO 输入结构、明白"配置引脚 = 管理电流路径"。

### 故事 3：一睡就醒——pending 中断
- **现象**：进休眠瞬间被唤醒（dt=0ms），永远进不了深睡。
- **根因**：WFI 前 KEYSCAN/EXTI13/USART2/DMA 有残留 pending 中断，WFI 一执行立刻被唤醒。
- **修复**：`pm_clear_pending_wake_irqs()` 逐个清外设中断标志 + NVIC pending。
- **面试点**：Cortex-M 的 WFI/pending 机制、低功耗进入前的标准流程。

### 故事 4：8ms tick 定时器挡住深睡（tickless 思想）
- FreeRTOS tick 由 8ms SDK 定时器注入（callBakSdkTimer → xTaskIncrementTick）；
- 该定时器 pending 会让 br_sleep() 每 8ms 被唤醒，永远深睡不了；
- 待机态删除定时器（sdk_timer_pause），退出待机恢复（sdk_timer_resume）。
- **面试点**：这就是 FreeRTOS 官方 tickless idle 的思想——空闲时停 tick、唤醒时补偿。
- ⚠️ **自测点**：tick 停了之后 app_now_ms()（sdk_timer_get_current_ms）还在走吗？90s 待机→休眠超时靠什么触发？我的推断是 ms 计数来自硬件自由计数器、8ms 定时器只负责注入 tick 和唤醒，**面试前请验证**。

### 故事 5：睡眠锁 br_sleep_lock
- 工作态**持锁** → br_sleep() 只进浅睡 IDLE（保证低延迟）；
- 待机态**放锁** → br_sleep() 可深睡。锁是计数器，release 循环到 0。

### 故事 6：IWDG 与休眠共存
- LSI 32KHz/256 = 125Hz，1250 tick = 10s 超时；休眠期间 LSI 停 → 看门狗不误触发；
- 睡之前踢一脚（IWDG_ReloadKey）→ 唤醒后有 10s 宽限；
- ⚠️ 注释提到一条"IWDG 复位 → main 检测 IWDGRSTF → 无 BLE 直接睡"的路径（pm_sleep_enter_no_ble），**面试前核对 main 里是否有此分支**。

## 四、软件设计亮点

1. **时间戳式空闲计时**（记录"最后活动时间戳"而非递减计数）+ **下溢保护**（49 天回绕检测，防误触发超时）；
2. **enter/exit 集中管理**：每个状态的进入/退出硬件动作集中在一个函数，转换幂等（同状态直接返回）；
3. **OTA 会话保护**：OTA 期间拒绝进入待机/休眠，process 只刷新活动时间戳；
4. **通知/回调解耦**：业务模块只调 `pm_activity_notify()`，不直接操作外设；所有状态变量 static；
5. **参数宏集中**（pm_config.h）：超时、连接参数全部宏管理，调试期快速可调；
6. **初始化时序坑**：pm_state_init 先于 BLE 栈执行时 peer_bonded_count() 必为 0，故有 `pm_state_sync_after_ble_init()` 在栈就绪后修正初始状态（绑定数据从 Flash 恢复到 RAM 后才能正确判断）；
7. **连接参数对标国标**：待机 50ms 取 GY/T 407-2024 §5.1.2.3 上限（5~50ms），工作 10ms + latency 40 符合附录 C.2。
