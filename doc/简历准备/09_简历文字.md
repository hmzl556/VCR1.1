## 主推版（5 条职责，旗舰项目用）

---

**蓝牙遥控器低功耗系统设计**（广电总局发起的量产项目）　2026.04 – 2026.08
BR1601x BLE SoC + Cat.1 模组 · FreeRTOS · Keil　|　团队 3 人，个人独立负责低功耗与 BLE 键控部分

面向广电总局的机顶盒蓝牙语音遥控器，集成 HID 键控、BLE 语音传输、4G 收视数据上报与远程 OTA 升级，整体对标国标 GY/T 407-2024。

- **低功耗系统设计（核心）**：依据国标状态定义设计六级低功耗状态机（配对/回连/工作/待机/休眠 + 静默），通过 BLE 连接参数分级切换（10ms/40 ↔ 50ms/100）、外设时钟门控、待机态事件间深度睡眠等手段逐层降功耗，并对照原理图完成**逐引脚电流审计**。待机态 500µA → **<10µA**、休眠态 **<10µA**（国标限值 65µA/20µA），按键 2.51mA、语音 5.39mA（限值 10mA/15mA），全部功耗指标远优于国标要求；
- **硬件问题攻关**：
  - 定位未上电 Cat.1 模组经 ESD 二极管被 UART 空闲高电平灌电（异常电流 ~500µA 且跳变）等引脚级漏电问题；以**洗板水对照实验**定位休眠态漏电根因（助焊剂残留/手汗），推动量产导入三防漆工艺；
  - 定位连续按键死机根因：**CAT1 发射峰值电流触发电池保护板过流保护**、供电瞬态跌落致 MCU 死锁（先以 IWDG 看门狗止血，后与电池厂商协同提高保护板限流阈值根治）；
  - 设计 CAT1 模组**按需上电策略**（仅数据上报/OTA 时上电、事务完成即断电），规避模组 7mA 常开功耗与 PSM 模式依赖基站不稳定的问题；
- **HID 键控通道**：因 SDK 自带 HOGP 服务与机顶盒存在 **CCCD 使能兼容性问题**，改为手动搭建 HID over GATT 服务表（Report/Boot 双通道、6 键 NKRO）；补充 DIS 服务 **PnP ID（VID/PID）**，解决机顶盒设备识别导致的静音键无响应；实现 44 键矩阵扫描链路（硬件+软件双重消抖、长按/短按/组合键互斥）与国标键值映射；
- **BLE 连接管理**：实现配对/回连/唤醒三种连接方式与绑定信息 Flash 持久化（magic+校验和防护）；通过 nRF Connect 抓包对比成品遥控器，定位并解决唤醒广播 **128-bit UUID 字节序与机顶盒待机扫描通道不匹配**的兼容性问题；
- **系统联调**：参与 Cat.1 数据上报（AT 指令状态机 + UDP + AES-128）与 OTA 升级（A/B 双分区 + 断点续传）开发及整机联调。

## 五个攻关故事（专业表述版，面试展开用）

### 故事 1：连续按键死机 —— 电池保护板限流（硬件岗最高含金量）
- **现象**：连续快速按键时遥控器死机，仅重新上电可恢复。
- **应急**：先引入 IWDG 看门狗（10s 超时）保证死机后自动复位——先止血。
- **定位**：死机场景均伴随 CAT1 数据上报；Cat.1 发射瞬间存在**安培级峰值电流**（23dBm 发射 + 协议栈活动），电池保护板过流保护 MOS 管**限流阈值偏低**，瞬间钳制电流 → 系统电源轨瞬态跌落 → MCU 欠压死锁。
- **根治**：与电池厂商协同提高保护板限流阈值，问题消失——用结果反向验证根因。
- **话术**："软件看门狗只是止血，根因在硬件电源路径——先保证现场能恢复，再沿'峰值电流→保护电路→电源完整性'把根因挖出来。"
- 可展开知识点：Cat.1 发射峰值电流量级（1~2A）、电池保护板（过流/过放 MOS）、瞬态压降与 MCU BOR 欠压复位、去耦电容的作用。
- ⚠️ 面试前确认：死机是复位还是死锁？示波器是否抓过 VBAT 跌落波形？电池 MOS 限流值前后各是多少？

### 故事 2：唤醒广播 UUID 反转 —— 适配对端的非规范实现
- **现象**：电源键第一次按下 STB 正常进待机（连接断开）；再按发唤醒广播，STB 无反应；配对/回连广播正常。
- **定位**：nRF Connect 抓包对比成品遥控器的唤醒广播，发现唯一差异——**128-bit Service Data UUID 字节序相反**。
- **原理**：BLE 规范规定 128-bit UUID 在 air 上按**小端**传输，接收方协议栈解析时翻转为标准大端再匹配；STB 待机态下连接已断开，广播由待机专用的低功耗扫描通道处理，该通道**不做字节序解析**、直接按原始字节与本地保存的 UUID（大端字符串）匹配；工作态完整协议栈则会自动翻转。同一 UUID 在两个接收路径下的"正确字节序"恰好相反——**唤醒包必须按待机路径的期望反转 UUID**。
- **话术**："不迷信规范，抓包看真实设备的实现——规范是给多数派用的，兼容性要适配少数派。"
- 可展开知识点：BLE 广播 AD 结构、UUID 字节序约定、Service Data、nRF Connect 抓包方法、双路径（工作态协议栈 vs 待机态扫描器）接收差异。

### 故事 3：静音键不生效 —— DIS 服务 PnP ID 与主机设备识别
- **现象**：静音键无效，但 adb 查看 STB 后台能收到正确的 HID 键值——链路本身正常，问题在主机侧按键→业务的映射。
- **方向**：甲方提示可能因未设置 VendorID/ProductID——主机依据 VID/PID **识别设备类型**并路由按键，遥控器未暴露 VID/PID 则按键无响应。
- **过程**：① 引入 Device Information Service（DIS，0x180A），用 SDK 原接口注册 PnP ID 特征（0x2A50，内含 VID/PID）；② STB 不主动 Read 该特征 → 回调方式返回值的路径走不通；③ 改用 `gatts_chr_ro_add` 注册，**特征值在服务注册时直接固化在属性表中**，规避"等主机 Read 回调"的兼容性问题。
- **话术**："先证明链路没问题（adb 看到键值），再怀疑主机识别，再补设备身份信息——问题定位要逐层排除。"
- 可展开知识点：DIS 服务（0x180A）、PnP ID（0x2A50）、主机按 VID/PID 路由 HID 设备、GATT 属性值两种提供方式（应用回调 vs 注册时固化）。
- ⚠️ 面试前确认：SDK 原接口下 STB 是否连 Read 都没发（抓包确认过吗）？gatts_chr_ro_add 与普通 add 在协议栈层面的差异最好能说一句。

### 故事 4：休眠态功耗超标 —— 板级工艺漏电（洗板水对照实验）
- **现象**：休眠态实测 50~60µA（国标限值 20µA），且读数**极不稳定**。
- **软件手段穷尽**：按休眠规范逐项处理——停广播、外设全关（LED/CAT1 串口/语音 ADC）、未用引脚配模拟输入、进 WFI 前清除全部 pending 中断（pm_sleep.c 的 pm_clear_pending_wake_irqs）等，电流纹丝不动。
- **转折**：偶然用**洗板水清洗电路板**后，休眠电流降到 10µA 以下——问题不在软件，在板子。
- **根因**：焊接残留助焊剂与手汗等**离子污染**在板面形成泄漏通路（漏电对温湿度敏感，故读数跳动）。
- **量产方案**：生产导入**三防漆**工艺，阻隔离子污染。
- **话术**："功耗调试的最后一道防线是板级工艺——软件手段穷尽后，用对照实验证明问题在板子本身。"
- 可展开知识点：助焊剂残留与离子污染、漏电流与温湿度关系、三防漆作用（防潮/盐雾/霉变）、对照实验方法（清洗前后数据对比）。
- ⚠️ 面试前确认：清洗用的溶剂与操作、清洗前后实测数据各是多少、三防漆选型。

### 故事 5：待机态功耗超标 —— 逐引脚电流审计（500µA → <10µA）
- **现象**：待机态初始方案用 SDK 自带的 standby 模式——但该模式**无法保持 BLE 连接**（国标强制要求待机态保持连接），且功耗 1mA 以上，方案被否。
- **换方案**：按芯片厂商建议改用 br_sleep() 深度睡眠（可保持 BLE 连接），功耗降到 500µA 量级，但读数在 400~600µA 间**跳动**——典型引脚漏电特征，怀疑 IO 配置问题。
- **方法**：对照原理图对每根引脚做**电流审计**（电平/上下拉/外部网络逐项核算），逐脚整改（对应 pm_standby.c 引脚配置注释）：
  - **PB4**（USART2 TX → 未上电 CAT1 的 LTE_RXD）：空闲高电平经模组 ESD 钳位二极管灌入其 VBAT 轨，模组半上电振荡——**500µA 的主犯**。修复：关 USART2 后将 PB4 配为推挽输出低；
  - **PB6**（VLTE 分压检测）：内部上拉经外接 4.7K 分压电阻对地白耗 ~74µA → 改模拟输入无上拉；
  - **PB5**：外部已有 10K 上拉，内部上拉冗余，CAT1 放电窗口 Q3 微导通时多耗 ~80µA → 浮空输入；
  - **PB11/12/13**（麦克风偏置网络）：内部上拉会给麦供电 → 模拟输入断电；
  - 未用引脚全部配模拟输入，消除浮空输入的振荡电流；
  - 外设时钟门控（SPI1/2、TIM1、USART1、WWDG、CRC）；删除 8ms 系统 tick 定时器使 br_sleep 可深睡；语音硬件全关（MICBIAS/PGA/AUDIOPLL）。
- **结果**：待机态降至 **<10µA**（国标限值 65µA），保持 BLE 连接的同时远优于国标。
- **话术**："逐引脚审计就是'配置引脚 = 管理电流路径'——每一脚的上下拉背后都是一笔电流账。"
- 可展开知识点：ESD 钳位二极管结构与灌电、GPIO 输入结构与浮空振荡、上拉电流计算（V/R）、时钟门控、tickless 深睡。
- ⚠️ 面试前确认：这部分逐脚修改（AI 辅助分析原理图后的配置）你还没有仔细过一遍——**面试前务必把 pm_standby.c 的引脚配置注释逐条读懂**，这是"逐引脚电流审计"这个简历卖点的全部弹药。

## 睡眠机制与时钟门控（高频问答，背熟）

**问：简历里的"外设时钟门控"指什么？**
答：CMOS 电路的功耗大头是动态功耗，外设只要时钟在跑就在翻转耗电。在待机态把 SPI1/2、TIM1、USART1、WWDG、CRC 的外设时钟经 RCC 关掉（现场先保存、退出恢复），外设静止且寄存器保留，功耗≈0，恢复无需重新初始化。类比：拔插头而不是按待机键。

**问：待机/休眠的低功耗是怎么实现的？**
答：睡眠机制用芯片 SDK 基础原语——待机态 br_sleep() 深睡、休眠态 WFI 睡眠。工程重点不在调用函数，而在**为深度睡眠创造条件**：
1. **tickless**：删掉 8ms 系统 tick 定时器，否则每个 tick 都唤醒 CPU，永远睡不深；
2. **睡前清理**：清 pending 中断（否则 WFI 秒醒）、关外设时钟、按原理图逐脚配置引脚；
3. **睡眠深度分级**：工作态持睡眠锁保证按键响应延迟，待机态放锁才允许深睡。

**金句**："睡眠函数只是'躺下'这个动作，能不能睡熟取决于睡前关灯关门清闹钟；而且实测证明，500µA 压到 10µA 以下靠的不是睡眠函数，是逐引脚审计——函数决定功耗下限，板级决定实际值。"
